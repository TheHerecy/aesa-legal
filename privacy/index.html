Aesa Agent Privacy Policy

Blackbox Intelligence Group LLC · Effective 18 October 2026

Aesa Agent is a native Android client. It does not run a local model and it has no developer backend. You bring your own provider: sign in or paste an API key, or point the app at an OpenAI-compatible URL you control. Chat content goes only to the AI provider you connect. Blackbox Intelligence Group LLC does not receive it. There is no analytics SDK and no ads.

What we collect

Blackbox Intelligence Group LLC does not collect, sell, or share your chats, keys, photos, or location. There is no analytics SDK, no crash SDK that uploads chats, no ads, and no required Aesa account.

Data that stays on the device:

  • Conversation history
  • Durable notes / memory
  • Provider configuration (API keys are not stored in the chat database)
  • An optional Brave Search API key, if you save one
  • Phone Access grants and a local audit of recent phone-tool executions
  • Flags on assistant messages (Play AI-generated content policy)
  • Monthly spending totals
  • A privacy request log

API keys are stored in EncryptedSharedPreferences backed by Android Keystore. You can delete chats, keys, notes, grants, settings, the request log, and spending totals in the app under Settings, Delete all local data.

Spending and the request log

Spending totals and a privacy request log are kept only on the phone. Blackbox Intelligence Group LLC does not receive them. In Settings, Spending and budgets shows the monthly totals. Privacy ledger is the request log.

The log records the time, provider, host, model, what was attached, tokens, and estimated cost for each chat, image, and search call. It records the kind of attachment, such as a photo, file, or location, and not the photo or file itself. API keys are never stored in the log. Sign-in calls are not logged. Only the newest 2,000 rows are kept.

"Save request text" is off by default. When you turn it on, the text sent to the provider is saved in the log, with keys stripped.

You can export the log to a file you choose, or clear it. Clearing the log does not reset monthly spend. Delete all local data removes the log and the spending totals along with the other data stored on the phone.

Data you send to third parties

When you send a message, the app transmits conversation text (and attached photos or files, if you attach them) to the provider you enabled, for example OpenAI, Anthropic, xAI, DeepSeek, Moonshot/Kimi, OpenRouter, Google Gemini, or a host you type (Ollama, LM Studio, vLLM, llama.cpp). Image prompts go to the image API of the xAI or OpenAI-compatible account you connected. Those providers are third parties you choose. We do not interpose a proxy.

If you save a Brave Search API key, search queries are sent to Brave Search (api.search.brave.com). Chats are not sent to Brave. The key is optional and stays on the device until you delete local data.

If you enable Phone Access and confirm a tool:

  • Location, clipboard text, or contact display info may be included in the next model turn, only after Confirm.
  • The Google Play version does not read notifications. It does not include a notification listener and does not read notification titles or text.
  • dial_number and compose_sms open the system dialer / SMS app. Aesa Agent does not place calls or send SMS.

LAN / cleartext

Custom endpoints on your LAN (for example http://192.168.x.x:11434/v1) may use unencrypted HTTP. That is required for typical homelab Ollama. Prefer Tailscale or HTTPS when you can.

Permissions

Used for app functionality, optional, not sold: Internet; Microphone (system speech recognizer); Camera (optional capture; Photo Picker is preferred); Location (one-shot, only when the location tool is confirmed).

The Google Play version does not request notification permission, a foreground service, or Notification Listener access, and it does not read notifications. A notification listener and a special-use foreground service (Phone Access status) exist only in a separately distributed sideload build. That sideload build can read active notifications only after you enable the system Notification Listener and confirm the tool.

The Play flavor does not request SMS, call log, Accessibility, all-files, overlay intercept, install-unknown-apps, notification listener access, or a special-use foreground service.

Security

TLS for non-LAN hosts. Certificate pinning is off in v1 so custom endpoints work. Auto Backup is disabled so keys are not included in cloud backup.

AI-generated content

Responses are generated by the AI provider you connect. You can flag any assistant message in-app.
